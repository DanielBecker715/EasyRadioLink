EasyRadioLink 1.1.0: **one radio instead of six**. Tune with the knob or buttons; modulation and sound follow the band
automatically. Everybody on the same frequency hears each other - there are as many channels as there are frequencies.
And the connection to the server is now **encrypted**, the voice **end-to-end encrypted**: only the stations tuned to a
frequency can hear it, not even the server.

**1.0 clients cannot connect to 1.1 servers (and vice versa)** - please update clients and servers together.

| File | Who needs it |

## New

- **One radio, 1.000 - 999.999 MHz.** It replaces the six radios that all received at the same time.
- **New radio window**: a backlit display with seven-segment digits, a big tuning knob (drag it round or use the mouse
  wheel), ▲ / ▼ keys, **STEP** (1 kHz up to 100 MHz; the digit that changes is underlined), direct entry (double-click
  the display, type e.g. `446.19375`, Enter), a volume knob, TX / RX, the speaker's name and the number of users on
  the frequency (if the server allows them). The window scales with the grip at the bottom right and remembers its
  position and size. The arrow keys tune (Up / Down) and change the step (Left / Right).
- **Automatic band plan**: the frequency decides the modulation, the radio sound and the band shown on the display.
  Sender and receiver apply the same plan, so everybody on a frequency always matches.

## Encrypted connection and end-to-end encrypted voice

- **Encrypted connection**: the connection to the server uses TLS 1.2/1.3. The password, names, frequencies and the user
  list can no longer be read or changed on the way; the password is no longer sent in clear text. Voice packets are
  encrypted and authenticated per user (AES-256-GCM, a new key for every connection); replayed or altered packets are
  dropped.
- **End-to-end encrypted voice**: every transmission (each PTT press) has its own random key, which only the stations
  tuned to the frequency receive - encrypted separately for each of them with a key pair that the client creates on
  every start (ECDH P-256; the private key never leaves the PC). The server passes the voice on but can't listen, and it
  can't move a transmission to another frequency. Whoever tunes in during a transmission gets the key and hears the
  rest of it; if a key doesn't arrive in time, the radio plays a scrambled sound instead. Recordings and the radio check
  echo keep working.
- **Server identity**: on its first start every server creates its identity `server-identity.pfx` (next to
  `server.cfg`) and shows its fingerprint in the server window, on the console and in `serverlog.txt`. EasyRadioLink
  remembers the fingerprint on the first connection (like SSH) and shows it under **Server Info**. If a server presents
  a different identity later, EasyRadioLink stops before sending anything - not even the password - and asks whether
  to *Connect anyway and trust the new identity*. An unreadable saved identity is never replaced silently (the user is
  asked), and a damaged `known-servers.json` stops all connections until it is repaired or deleted - it is never
  overwritten.
- What the server still sees: who is connected, who is tuned to which frequency and who transmits when. Anybody who
  can connect to a server can tune to any frequency - set a password to keep strangers out. Details and the threat
  model: *Security* in the README.
- The server limits the new voice key messages to a burst of 20, then 10 per second per user, and forwards each
  listener only its own key; all flood protections of 1.0 (connection limits, password lockout, rate limits) stay in
  place, a TLS handshake must finish within the 15 s login time, and refused connections are summarised in the log once
  a minute.

## Removed

- Radios 2-10: radio selection and its hotkeys, "radio switch works as PTT", transmitting on several radios at once
  and the balance settings of radios 2-10 (one "Radio balance" remains).
- Guard receiver, the per-radio encryption setting of 1.0 (controls, hotkeys, encryption tones - voice is now always
  end-to-end encrypted, see above) and the per-radio sound selection - the band decides the sound now.
- Preset channels: the client's preset files and presets folder, the server's `Presets` folder.
- Radio layouts: `radios.json` and `radios-custom.json` on the client, `server-radios.json` on the server.
- Server settings and command-line options: *Allow radio encryption* (`--allow-encryption`), *Strict radio encryption*
  (`--strict-encryption`), *Server channel presets* (`--server-presets`) and *Server radio layout*
  (`--server-radio-layout`). The command-line options are still accepted but ignored (see *Upgrading from 1.0*).
- Radio window transparency and the recording option "one file for all radios" (recordings now have one file for the
  radio).

## Upgrading from 1.0

- **Client**: extract the new version and use it instead of the old folder. Your settings in `%AppData%\EasyRadioLink`
  are kept; the radio continues on the frequency and volume of the radio you had selected last. Push-to-talk,
  frequency up / down, volume and the radio window hotkeys keep working; hotkeys of removed features are ignored. Old
  preset files and `radios-custom.json` are no longer read and can be deleted.
- **Everybody at once**: 1.0 clients cannot connect to 1.1 servers and 1.1 clients cannot connect to 1.0 servers (the
  connection is encrypted now). A 1.0 client shows "incompatible server"; a 1.1 client connecting to a 1.0 server
  reports that servers older than 1.1 can't be used. Update the server and all clients together.
- **Server**: copy `server.cfg` (and `banned.txt`) into the new version as before. The first start creates the server
  identity `server-identity.pfx` next to `server.cfg` and prints its fingerprint - share it with your users, keep the
  file private and copy it along with `server.cfg` on every later update (a new identity makes every user confirm it
  once). The command-line server still accepts `--allow-encryption`, `--strict-encryption`, `--server-presets` and
  `--server-radio-layout`, so existing start scripts and service files keep working, but it ignores them and prints a
  warning - remove them when convenient. The lines `ALLOW_RADIO_ENCRYPTION`, `STRICT_RADIO_ENCRYPTION`,
  `SERVER_PRESETS_ENABLED` and `SERVER_RADIO_PRESET_ENABLED` in `server.cfg` are ignored and can be deleted, just like
  the `Presets` folder and `server-radios.json`.
- **Clients**: on the first connection to each server EasyRadioLink remembers the server's identity; there is nothing
  to set up.
